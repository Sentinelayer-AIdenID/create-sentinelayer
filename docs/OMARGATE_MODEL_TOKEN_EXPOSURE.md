# Opt-in model-token exposure cap

`omargate deep --max-model-token-exposure 5` reserves exposure before each model request. It covers one CLI invocation under the bundled, versioned standard-rate policy. It is **not an unconditional invoice guarantee or account spending limit**. Existing `--max-cost` behavior remains unchanged without this option; in exposure mode the shared cap replaces that estimated post-completion threshold.

Select the provider/model explicitly or use your existing configuration. This option never changes the selected route or model. The supported exact routes are:

| Provider/model | Endpoint and processing | Input ceiling | Output ceiling | Input/output USD per million |
| --- | --- | ---: | ---: | --- |
| `openai` / `gpt-5.3-codex` | `/v1/responses`, default tier, global API | 400,000 | 4,096 | 1.75 / 14 |
| `anthropic` / `claude-sonnet-4-6` | `/v1/messages`, standard-only tier, global inference | 1,000,000 | 2,048 | 3 / 15 |

The Anthropic route explicitly requests global inference and rejects mismatched geography/speed in usage. Workspace restrictions remain enforced by Anthropic. The policy is valid from October 21, 2026 through October 27, 2026 UTC; expiry or an unknown exact route refuses before sending. Refreshing it requires rechecking rates and limits, changing its version, and reviewing the change. The timestamp is not a provider quote. Account-specific fees, taxes, rate changes and external provider violations are outside this policy's assurance.

Only positive USD decimals with up to nine decimal places are accepted. Zero, negative, nonfinite and malformed values fail explicitly. No uncapped sentinel is accepted here. Legacy zero semantics are unchanged when this option is absent. This mode rejects `--no-ai`, dry runs and TypeSafe classification; none can stand in for the requested live generation contract. The managed proxy and Google are unsupported until their complete downstream exposure can be established.

Bounded direct-provider usage is recorded **locally only**. The existing remote `billing/v1` recorder reprices tokens for ledger/quota projection and has no non-billable BYOK exposure contract. This mode never invokes it and rejects `--require-usage-ledger` before provider dispatch. An explicit `--notify-session` supplies the local accounting session identifier only; it does not create remote billing entries. Artifacts explicitly report `bounded_direct_usage_local_only`. Without the exposure option, existing session-ledger behavior remains unchanged.

Reservations use exact integer nano-USD and the documented full context window as a conservative input allowance, including framing: $0.757344 per OpenAI request or $3.030720 per Anthropic request. OpenAI's rendered model page lists a 400,000 context window and 128,000 maximum output. A normalized docs response listed 272,000 maximum input, but that narrower bound was not established by the rendered page; this policy uses the full 400,000 rather than subtracting maximum output. There is no character/token approximation, count endpoint call, per-persona minimum or hidden retry. The entire prompt is sent; the mode does not trim files or personas. Each request has one attempt, an explicit total generated-token ceiling, no redirect, tools, background/stream continuation, rescue model or requested cache write. OpenAI's automatic cache hits receive no assumed discount: all reported input is charged at the ordinary policy rate. Anthropic cache usage is unsupported and freezes the run.

All outer persona and inner partition workers share one controller. Work waits when existing reservations may release enough capacity. The controller settles using valid provider usage and releases unused exposure. Timeout, failed HTTP response, invalid/missing usage or changed pricing identity retains the full hold and stops new admissions. Already submitted work is drained. No uncertain request is replayed, and restarting creates a separate invocation rather than resuming this budget.

Paying for a response does not complete a review. OpenAI must report completed status; Anthropic must report an ordinary end of turn without a refusal. Truncated, failed or invalid structured reviews remain incomplete and blocking, retaining available findings. Partial coverage never satisfies the full gate.

JSON and artifacts expose `modelTokenExposure`: exact cap/settled/reserved amounts, policy/version/hash, request hashes and attempt states. Per-call AI artifacts retain authoritative provider usage and completion metadata. These figures measure token exposure under the policy; they are not provider invoices. A fresh run may still stop within $5 before every partition completes. For a 923-request plan, allowing every OpenAI request its 4,096 output tokens alone requires $52.93 of worst-case output allowance. The CLI does not increase your limit or lower output limits to hide that fact.

Cost-history entries, local usage events and AI reports label the token basis as `provider_reported` and the cost basis as `pinned_rate_conservative_exposure`, with the policy hash. Reported cache counters are retained even though this policy grants no automatic-cache discount. Compatible `costUsd` totals in these local records therefore mean conservative policy exposure; provider/customer invoice amounts are unknown, not inferred from those totals.

Assurance is reported separately from the reservation ledger. `assuranceStatus: "uncertain"` and `assuranceValid: null` mean a sent request has no trustworthy settlement; its whole reservation remains held. A known provider limit or pricing-scope violation reports `assuranceStatus: "violated"` and `assuranceValid: false`, even when the ledger's retained ceiling is still below the cap. Recognized numeric usage, exceeded counters and any observed excess under the pinned rates are retained as evidence, without provider error text or unrecognized payload fields. These observations are not silently clamped to the reservation or represented as a valid bound.
